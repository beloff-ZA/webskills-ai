# V3 — Natural On-Page SEO and Content Architecture

## Purpose
Build search relevance as a result of useful, specific, readable content and accessible information architecture. SEO must follow the user's intent and page's purpose, not force the visual design into keyword-heavy text blocks. Apply this to all indexable pages.

## 1. Establish page intent
Before layout or writing, define: page type, intended audience, primary question/task, real-world offering, geographic relevance if genuine, primary conversion action, and one distinct search intent. A page without unique user value should not be created merely to capture a keyword variant.

## 2. Natural language and information architecture
- Answer the visitor's actual question in the first meaningful content region. A hero headline should name the offering, not rely only on a slogan.
- Use an accurate, distinctive H1 aligned with the visible subject and page title; generally one clear primary H1 per page, with H2/H3 used for real nested sections. Do not use headings solely to size text.
- Choose terminology customers naturally use. Include relevant synonyms only where they help comprehension. Never enforce keyword densities, minimum repetition counts or exact-match phrases.
- Include evidence and useful decision facts where available: services, eligibility, process, location/service area, session length, pricing or how to request it, accessibility, delivery, staff qualifications. Flag unknown facts for the client rather than inventing them.
- Paragraphs and labels should be concise, plain-language, accurate and specific. Avoid AI boilerplate, vague benefit stacks, empty superlatives, generic FAQs, and "SEO paragraphs" at the bottom of pages.
- Link internally to truly related pages with descriptive anchor text; never use repetitive sitewide keyword anchors. Navigation must use real hrefs.
- Use descriptive, non-stuffed alt text for informative images; empty alt for purely decorative images. Provide captions only if useful.
- Do not introduce location pages for places the business does not actually serve. No invented opening hours, certifications, ratings, testimonials, customer numbers or awards.

## 3. Content-first page layout
Map question -> evidence -> action. Example for a small coaching service:
1. H1: actual service and audience, optionally verified service area.
2. First paragraph: what is offered, for whom, and why it fits.
3. About coach: real credentials and approach, no invented claims.
4. Sessions: formats and practical details.
5. Where/how: verified location, availability, enquiry.
6. CTA: clear next step.
The design can vary substantially; this order is not a universal template. Each section must earn its place. Accessibility, visual rhythm and readability take priority over arbitrary SEO component counts.

## 4. Semantic HTML requirements
- Correct HTML language, charset and viewport configuration.
- Use header/nav/main/footer landmarks and meaningful section/article/aside elements where appropriate; avoid meaningless section wrappers.
- One identifiable main content landmark; structured headings; use ol/ul for actual lists and button for actions rather than clickable divs.
- Use native links with href for navigation; forms need labels and meaningful validation.
- Make core content and links available in HTML or reliably rendered, crawlable output; do not require interactions to reveal all essential content.
- Avoid hiding keyword text, cloaking, doorway pages and generating near-identical pages.

## 5. Editing and QA
Check each page for: clear answer above the fold; unique value; evidence-backed claims; navigability; meaningful headings and alt text; natural copy that makes sense aloud. Ask: would the page still be useful without a search engine? If not, rewrite.
Record unknown client data and exclude unsupported assertions. Do not claim search rankings are guaranteed.
