# Design review: evidence-led, skeptical
Assess (1) project fit (2) composition (3) hierarchy and typography (4) communication (5) imagery and material treatment (6) originality and source distance (7) responsive behaviour (8) accessibility (9) commerce usability if applicable (10) implementation quality.

## Review cycle
1. Inspect real output when possible, not only code or descriptions.
2. Record the three strongest decisions with reasons.
3. Record up to five highest-impact weaknesses with evidence (page/section/viewport).
4. Identify whether each issue is a usability defect, generic convention, derivative similarity, inconsistency or engineering defect.
5. Correct issues in descending severity and re-inspect.
6. Distinguish checks actually executed from assumptions.

A beautiful visual can fail if customers cannot use it. A functional site can fail if indistinguishable from a template. Neither failure is fixed by adding animation.
